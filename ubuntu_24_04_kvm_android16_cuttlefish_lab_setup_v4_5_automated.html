From clean Ubuntu VM to running Android 16 with one script

This streamlined edition replaces the manual installation sequence in v3. Learners provide only the environment and matching Android artifacts; the bootstrap installs the exact host prerequisites, configures Cuttlefish, launches it and runs acceptance checks.

2. Download the two Android 16 artifacts

Official Android Continuous Integration site:
https://ci.android.com/

Artifact 1 — Android device images

From the selected Android 16 Cuttlefish build, download:

aosp_cf_x86_64_phone-img-<BUILD_ID>.zip

Depending on the exact CI target/build naming, the x86_64 Cuttlefish phone-image artifact can appear with a closely related name. The official AOSP instructions identify the x86_64 phone image artifact in the build's Artifacts panel.

Artifact 2 — matching Cuttlefish host package

From the same build's Artifacts panel, download:

cvd-host_package.tar.gz

Never reuse a host package from a different build. Host binaries and device images should be treated as one matched pair.

Exact Android CI navigation

  1. Open Android CI.
  2. Search/select branch android16-release.
  3. Find the x86_64 Cuttlefish phone target aosp_cf_x86_64_only_phone-userdebug.
  4. Choose a green successful build.
  5. Click the build and open Artifacts.
  6. Download the x86_64 phone image ZIP.
  7. From that same build, download cvd-host_package.tar.gz.
  8. Put both downloaded files beside the setup script in the learner's home directory.
Why the branch is explicit: this lab is pinned to Android 16. Avoid a moving “latest release” branch because it can advance to Android 17 or later and cause the final Android 16/API 36 acceptance check to fail.
Official AOSP Cuttlefish instructions:
https://source.android.com/docs/devices/cuttlefish/get-started
v4.4 launcher compatibility: current x86_64 host packages can expose bin/cvd_internal_start rather than bin/launch_cvd. This guide now launches the extracted CI bundle with cvd_internal_start first and uses launch_cvd only for legacy packages. The unrelated system /usr/bin/cvd device database is not used for local artifact startup.

Before running the script, the directory should look like this

$ ls -lh
setup-ubuntu24-android16-cuttlefish-lab-v4.5.sh
cvd-host_package.tar.gz
aosp_cf_x86_64_phone-img-<BUILD_ID>.zip

# Ubuntu 24.04 + Android 16 Cuttlefish one-command lab bootstrap v4.5
# Target: x86_64 Ubuntu 24.04 VM with nested KVM
# Android 16 artifacts: https://ci.android.com/
# AOSP Cuttlefish download instructions: https://source.android.com/docs/devices/cuttlefish/get-started
# Use branch android16-release, target aosp_cf_x86_64_only_phone-userdebug,
# and download cvd-host_package.tar.gz + the x86_64 phone image from the SAME green build.
# v4.4 launches local CI bundles with bin/cvd_internal_start (current) or bin/launch_cvd (legacy).
set -Eeuo pipefail

  local rc=$?
  printf '\n[FAIL] Setup stopped during stage: %s\n' "$CURRENT_STAGE" >&2
  printf '[FAIL] Exit code: %s\n' "$rc" >&2

      sudo -u "$CVD_USER" env HOME="$RUNTIME" \
        "$RUNTIME/bin/stop_cvd" >/dev/null 2>&1 || true
    fi
  fi
  exit "$rc"
}

find_artifact_pair() {
  local dir
  for dir in "$PWD" "$CVD_HOME"; do
    [[ -d "$dir" ]] || continue
    local host="$dir/cvd-host_package.tar.gz"
    [[ -f "$host" ]] || continue

    if [[ -n "$CVD_IMAGE_ZIP" ]]; then
      local explicit="$CVD_IMAGE_ZIP"
      [[ "$explicit" = /* ]] || explicit="$dir/$explicit"
      if [[ -f "$explicit" ]]; then
        ARTIFACT_DIR="$dir"
        HOST_PACKAGE="$host"
        IMAGE_ZIP="$explicit"
        return 0
      fi
    fi

    local -a images=()
    shopt -s nullglob
    images+=("$dir"/aosp_cf_x86_64_phone-img-*.zip)
    images+=("$dir"/aosp_cf_x86_64_only_phone-img-*.zip)
    shopt -u nullglob

    if [[ ${#images[@]} -eq 1 ]]; then
      ARTIFACT_DIR="$dir"
      HOST_PACKAGE="$host"
      IMAGE_ZIP="${images[0]}"
      return 0
    elif [[ ${#images[@]} -gt 1 ]]; then
      echo "[FAIL] Multiple Cuttlefish phone image ZIPs were found in $dir:" >&2
      printf '  %s\n' "${images[@]}" >&2
      echo >&2
      echo "Choose one explicitly, for example:" >&2
      echo "  CVD_IMAGE_ZIP='${images[0]}' ./$SCRIPT_NAME" >&2
      return 2
    fi
  done
  return 1
}

set -Eeuo pipefail

discover_serial() {
  local config env_file serial=''
  config="$(
    find "$R/cuttlefish/instances" \
      -type f -name cuttlefish_config.json \
      -print -quit 2>/dev/null
  )"

  if [[ -n "$config" ]]; then
    serial="$(
      jq -r '.. | objects | .adb_ip_and_port? // empty' \
        "$config" 2>/dev/null |
      head -n 1
    )"
  fi

  if [[ -z "$serial" ]]; then
    env_file="$(
      find "$R/cuttlefish" \
        -type f -name cuttlefish.env \
        -print -quit 2>/dev/null
    )"
    if [[ -n "$env_file" ]]; then
      serial="$(
        sed -nE 's/^export ANDROID_SERIAL="?([^"]+)"?$/\1/p' \
          "$env_file" |
        head -n 1
      )"
    fi
  fi

  printf '%s\n' "$serial"
}

7. What the script prevents automatically

Common setup mistakes removed

  • Wrong Ubuntu/architecture continues no further.
  • Missing VMX/SVM or /dev/kvm fails before package installation.
  • Missing or duplicate Android image ZIP fails early.
  • Corrupt host/image archives fail before extraction.
  • Current and legacy Cuttlefish launcher layouts are auto-detected; bin/launch_cvd is no longer mandatory.
  • Missing Cuttlefish groups are created and applied automatically.
  • Required vhost modules and device nodes are validated.
  • Malformed/empty fetcher_config.json is quarantined.
  • ADB serial is discovered dynamically; IP is not hard-coded.
  • Crosvm exit and Android boot timeout produce a clear stage failure.
  • Wrong Android release/API is caught by the final validator.

Safe rerun behavior

If the same image is already extracted and critical runtime files exist, the script preserves Android data and reuses the runtime. If a previous setup stopped before extraction completed, rerunning rebuilds the incomplete runtime.

Use RESET_CVD=1 only when an intentional clean Android state is required.

8.1. Android 17 / API 37 appears in an Android 16 lab

Interpretation: if the validator reaches ADB, boot, SELinux and networking successfully but reports: 
[FAIL] Android release 17
[FAIL] API 37

the Cuttlefish host setup is working. The selected device image is simply the wrong Android release for this lab.

As of June 2026, AOSP's moving android-latest-release branch points to Android 17, while the fixed android16-release manifest remains Android 16. For this guide, download from the fixed Android 16 branch/build.

When more than one phone image ZIP is in the directory

CVD_IMAGE_ZIP="$HOME/Downloads/aosp_cf_x86_64_only_phone-img-<ANDROID16_BUILD_ID>.zip" \
  ./setup-ubuntu24-android16-cuttlefish-lab-v4.5.sh

v4.5 refuses to guess when multiple image ZIPs are present. Changing the selected image filename automatically causes the runtime to be re-extracted.

8.1. Fixed in v4.4 — cvd start: “no devices present”

Symptom: 
Using current Cuttlefish frontend: /usr/bin/cvd start
Command `start...` is not applicable: no devices present

The Android image and KVM environment are not the problem. The system /usr/bin/cvd frontend maintains its own Cuttlefish device/group state and had no registered device to start.

For a CI host package extracted beside the Android device images, v4.4 now uses the launcher shipped inside that same host package:

/opt/cuttlefish/android16/bin/cvd_internal_start

On older host packages, it falls back to:

/opt/cuttlefish/android16/bin/launch_cvd

AOSP source describes cvd_internal_start as the start entry point that invokes assemble_cvd and run_cvd; it was previously named launch_cvd.

8.1. Fixed in v4.3 — TUN preflight interface-name error

Symptom: 
Error: argument "cvd-tun-preflight-xxxxx" is wrong: "dev" not a valid ifname

This does not mean /dev/net/tun is broken. Linux network interface names are limited to 15 characters, and the older bootstrap generated a name that was too long.

v4.3 uses a short name such as cvdtun14687, verifies that the TUN interface can be created and brought up, then deletes it immediately.

8. Only three prerequisite failures need infrastructure help

❌ No VMX/SVM or /dev/kvm

Fix nested virtualization and CPU host-passthrough on the physical KVM host. Installing more packages inside Ubuntu cannot fix this.

❌ Android artifacts missing

Download the Android 16 x86_64 phone image and cvd-host_package.tar.gz from the same successful CI build.

❌ Repository unreachable

Provide outbound HTTPS/DNS or the organization’s approved proxy/repository path. The bootstrap deliberately does not invent proxy settings.
